# Spreelo v144.263 — Credit balance self-heal for social connections

## Root cause fixed
Facebook page selection, Instagram OAuth and TikTok OAuth could all complete the provider-side login successfully and then fail inside Spreelo with:

`No Spreelo credit balance exists for this account.`

The free-trial/social-account protection expects `user_credit_balances` to exist, but some ordinary Free workspaces had never received that row.

## Changes
- Added server-side `ensureStandardSpreeloCreditBalance()` in `lib/freeTrial.js`.
- Social trial preflight now initializes a missing standard Free balance before checking trial eligibility.
- Social trial authorization performs the same defensive initialization before granting the trial.
- Server-side free-trial refresh also self-heals a missing balance row, which lets billing status recover affected accounts too.
- Added SQL migration `supabase/v144_263_credit_balance_self_heal.sql` / `spreelo-v144.263-SQL.sql` that:
  - backfills missing balance rows for existing `auth.users`,
  - adds a server-only helper to initialize a standard balance safely,
  - adds an `auth.users` signup trigger so future accounts cannot miss the balance row.
- Existing paid/trial balances are never overwritten; inserts are only for users with no balance row and are conflict-safe.

## Deploy order
1. Run `spreelo-v144.263-SQL.sql` in Supabase SQL Editor.
2. Deploy the v144.263 application zip.
3. Retest Facebook, Instagram and TikTok connection flows.

## Expected result
- Existing affected Free accounts immediately receive a standard locked Free balance (0 spendable credits, 100-credit offer waiting for eligible social verification).
- Facebook/Instagram/TikTok no longer fail merely because the balance row was absent.
- If a social account has already consumed a free trial, the existing explicit trial-restriction UI remains in control instead of a generic provider error.
