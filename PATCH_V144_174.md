# Spreelo v144.174 — Rescue Carousel Retry + 5/5 Completion Gate

Base: **v144.173**.

## Scope
This patch intentionally leaves the ordinary carousel engine untouched. It changes only Admin/Rescue carousel regeneration behavior.

## Changes
- A Rescue carousel remains `generating` while slides are being created; it is not placed in approval before rendering is complete.
- Each slide still uses the exact same verified product, Sol-locked slide copy, and shared carousel design brief as before.
- If a full GPT-Image carousel slide fails generation, upload, or product-identity review, that same slide gets one additional full-design attempt.
- A raw authoritative product image may be retained internally as a safety artifact, but it no longer counts as a completed rendered slide.
- Rescue can become `pending_approval` / `ready` only when **5 of 5 slides** are genuinely rendered full carousel designs.
- If any slide is still incomplete after the retry, the post remains in `needs_repair`, the work item remains `rescue_status = needed`, and the occurrence is not marked rescued/resolved.
- Attempt count and attempt errors are stored in slide metadata for diagnosis.

## Explicitly unchanged
- Exactly five products / five slides.
- Slide 5 remains product 5 plus closing CTA; no sixth AI outro.
- Sol carousel planning and locked copy.
- GPT-Image carousel prompt and identity-review logic.
- v144.173 fresh-first product selection and safe reuse-after-exhaustion behavior.
- Calendar-campaign theme/product relevance protections.
- No database migration / SQL required.
