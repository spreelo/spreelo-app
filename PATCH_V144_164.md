# Spreelo v144.164 — Explicit calendar campaign scope

## Scope

Targeted classification fix on top of v144.163. No changes to Product Engine discovery, Store Map discovery, bounded web-research fallback, publishing, billing, Social Channels or database schema.

## Problem

Ordinary AI Content Studio plans can legitimately store strategic fields such as `campaign_phase`, `marketing_angle`, `campaign_goal`, `strategy_notes` and campaign-style sequence metadata. The generation route previously treated the presence of any of those fields as proof that the rule came from the Calendar Campaign flow. This could send an ordinary product post into the heavier campaign-fit product-selection path.

## Changes

- `isCampaignScopedWebsiteRule()` now uses the existing explicit persisted discriminator: `queue_source = "campaign"`.
- Strategic planning metadata alone can no longer turn a normal `content_studio` rule into a Calendar Campaign rule.
- Real Calendar Campaign slots remain unchanged: Automation already persists them with `queue_source = "campaign"`.
- Existing-rule editing/loading in AI Content Studio now uses the same explicit `queue_source` signal, preventing ordinary strategic plans from reopening as campaigns.
- All Product Engine, Store Map and web-research fallback code paths are left intact. If an ordinary post cannot find/lock a local product, the normal bounded web-research fallback can still run exactly as before.

## Database

No SQL migration is required. `queue_source` already exists and is already written as `campaign` for Calendar Campaign slots and `content_studio` for ordinary AI plans.
