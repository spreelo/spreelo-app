# Spreelo v144.180 — Cardless Free Trial + Abuse Guard + Analysis Limits

Base: **v144.179** (`BRAND-429-RESCUE-COST-GUARD`)

## IMPORTANT DEPLOY ORDER

**This version requires a Supabase SQL migration.**

1. Set a stable Vercel secret named `SPREELO_TRIAL_FINGERPRINT_SECRET` (long random value; keep it stable over time).
2. Run `supabase/v144_180_free_trial_social_abuse_analysis_limits.sql` in Supabase.
3. Only after the SQL succeeds, deploy the v144.180 application ZIP.

Do **not** deploy the application before the migration. The app expects the new trial state columns, social-account trial registry, and analysis quota RPCs to exist.

## What changed

### 1. Cardless Free trial

- New ordinary Free accounts present a **100-credit free offer immediately**.
- The 100 credits are **not spendable in the database while locked**. The UI shows the offer from `free_trial_credit_amount`, while `credits_remaining` stays `0`.
- No Stripe checkout or card is required to activate the Free trial.
- Connecting one eligible, verified social account unlocks the 100 credits atomically.
- The **14-day trial starts when the eligible social account is verified**, not when the Spreelo account is created.
- Locked/expired Free-trial accounts are stopped server-side before automation AI generation, including stale reserved-credit cases.
- Free supports **1 connected social account**; recurring schedules remain paid-plan only.

### 2. One Free trial per verified social account

- Social trial eligibility is based on the platform plus the verified external social-account ID.
- The anti-abuse registry stores a deterministic **HMAC fingerprint**, not the raw external account ID.
- The HMAC now requires the dedicated, stable `SPREELO_TRIAL_FINGERPRINT_SECRET`; it no longer falls back to the Supabase service-role key, so rotating Supabase credentials cannot silently invalidate trial-history matching.
- Trial claim RPC is executable only by `service_role`.
- OAuth flows preflight the verified social identity before activation.
- If a social account has already activated a Spreelo Free trial on another account, the new Free account is blocked and shown a translated popup with a **View plans** action.
- Reconnecting the same social account is allowed only while its original Free trial is still active; an expired/used Free trial must upgrade before reconnecting it.
- Race-condition losers are failed closed and any saved OAuth tokens are cleared.
- Trial social/domain abuse history survives account/brand deletion in privacy-minimized form.
- Existing business-domain trial history remains a secondary abuse signal.

### 3. Old Stripe-gated trial path removed from active flow

- Stripe no longer starts a Spreelo trial.
- No `trial_period_days` checkout parameter.
- No Stripe trial-eligibility checkout gate.
- No Stripe webhook grant of the promotional 100 credits.
- Old Stripe trial reservation RPC entry points are dropped by the migration.
- Stripe is now used when the customer actually chooses Starter/Growth/Pro (or buys allowed paid add-ons).
- The paid subscription state RPC keeps its old signature for compatibility, but v144.180 always calls it with `p_is_trial=false` and `p_trial_credits=0`.

### 4. Brand-analysis usage limits

Customer-triggered analyses now use plan-specific daily and monthly quotas:

| Plan | Daily | Monthly |
|---|---:|---:|
| Free | 2 | 4 |
| Starter | 3 | 10 |
| Growth | 6 | 25 |
| Pro | 10 | 50 |
| Admin | Unlimited | Unlimited |

- Existing **1-minute cooldown** is retained.
- Daily reset: midnight in the account's captured timezone.
- Monthly reset: first day of the next month in that timezone.
- Timezone is stored per account so changing browser timezone cannot be used to reset quota repeatedly.
- Only customer-triggered analysis entry points claim quota.
- Internal worker / Rescue / annual calendar jobs do not consume the customer quota.
- If durable job creation fails before work starts, the quota claim is released by **service-role server code only**. Customers cannot call the release RPC themselves.
- Internal quota request keys are not returned to the browser.
- Repeated attempts after a daily/monthly limit has already been reached are counted in a bounded per-day counter for abuse monitoring.
- Brand Profile shows `Today X/Y` and `This month X/Y`.
- Daily/monthly/cooldown limits show translated dialogs with the exact next allowed/reset time.

### 5. Admin usage alerts

Admin email alerts are deduplicated and can trigger for:

- monthly quota reached,
- daily quota reached,
- repeated analysis of the same brand (3+ in 24h),
- 75%+ monthly usage **materially ahead of calendar pace**.
- repeated attempts after an already-reached daily/monthly analysis limit.

At most one highest-priority usage alert is selected per request, and durable alert keys prevent repeated email flooding for the same period. Repeated blocked-limit attempts trigger only after the third hit and are deduplicated per day/reason.

### 6. Brand-plan limits retained

Existing plan limits remain unchanged:

- Free: 1 brand
- Starter: 1 brand
- Growth: 2 brands
- Pro: 5 brands
- Admin: bypass

The existing translated `PlanLimitModal` and backend database enforcement remain in place. When the customer has filled the brand allowance, Spreelo blocks creation and offers **View plans**.

### 7. Internationalization

All newly added customer-facing UI copy uses Spreelo translation keys with English source strings in `lib/i18n/defaultLabels.js`.

This includes:

- Free-trial locked/active/used messages,
- social trial-reuse restriction dialogs,
- analysis usage counters,
- analysis daily/monthly/cooldown dialogs.

### 8. Account deletion/privacy

- Trial claim rows are anonymized before account deletion (`user_id` and `brand_profile_id` removed) while the minimum fingerprint/domain abuse evidence is retained.
- OAuth access/refresh tokens are not part of the durable anti-abuse identity.
- Analysis usage rows are removed with account deletion.

## Intentionally unchanged

- Product discovery/selection logic
- 5-product carousel creative pipeline
- Carousel product-image rendering / identity review
- Calendar campaign theme matching
- v144.179 brand 429 Rescue/cost guard behavior
- Publishing provider behavior

The automation worker received only a pre-generation Free-trial credit-state guard; the product/carousel generation implementation itself was not changed.
