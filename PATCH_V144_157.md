# Spreelo v144.157 — persistent translation integrity

This patch keeps English as the single authored UI/email source language and uses `ui_translation_packs` as the shared persistent cache for every other supported locale.

## Changes

- Added per-key English source fingerprints inside translation-pack metadata. New or changed English source keys are the only keys eligible for regeneration.
- Added a database-backed single-flight lease so concurrent first visitors do not independently translate the same locale/namespace.
- Preserved existing translated labels and existing `locale + namespace` packs.
- Added stronger AI translation validation for placeholders, unchanged English, likely-English output and required target scripts.
- Removed manually authored non-English email packs and the Swedish sign-in override.
- Routed language suggestion, home reference, brand, calendar, automation, image/video background management, OAuth completion and current admin surfaces through translation keys.
- Fixed namespace mismatches and missing translation keys.
- Converted operational/rescue source copy that was authored in Swedish to English.
- Added `supabase/v144_157_translation_cache_integrity.sql` / `spreelo-v144.157-SQL.sql` to guarantee the unique cache key required by single-flight translation.

## Deployment

Run `spreelo-v144.157-SQL.sql` in Supabase before deploying the application build. The migration is additive and does not clear translation labels. If duplicate rows already exist for the same `locale + namespace`, the migration deliberately stops instead of deleting a translation pack automatically.

Existing packs that predate source fingerprints are seeded with the current source fingerprints without an AI call when their translations are otherwise usable. From that point forward, changing an English value under the same key invalidates only that key.
