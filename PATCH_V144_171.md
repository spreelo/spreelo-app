# Spreelo v144.171 — Calendar Campaign Rescue Validation

## Purpose
Make Rescue campaign-aware for every post format that originates from Spreelo's campaign calendar, without changing ordinary/non-campaign Rescue behavior.

## What changed
- Added a shared server-side Campaign Rescue validator.
- Validation is required only when the original automation rule snapshot has `queue_source = campaign`.
- The ORIGINAL saved `rule_snapshot` is authoritative. A later edit to the live automation rule cannot redefine the failed campaign Rescue. Legacy work items with no snapshot fall back to the live rule.
- Product Rescue (`single_product`, `product_carousel`, `product_reel`, `ai_product_video`) is checked against the original campaign theme, goal, customer need, marketing angle, product strategy, match terms, search queries and original task/strategy.
- Product carousels require every rescued product to fit; one materially off-theme product blocks the whole package.
- Source-research Rescue (FAQ, Tips, Mini guide, Checklist, Problem→Solution, AI-image/theme posts and other non-product formats) is checked for task/campaign relevance before import is accepted.
- Event/holiday words do not have to appear literally in product titles. The validator uses the campaign strategy rather than naive keyword matching.
- Discounts/offers are never inferred merely because a campaign is Black Friday or another sales occasion.
- Calendar-campaign validation fails closed: if the validator cannot run, Rescue is not marked ready.
- Ordinary/non-calendar Rescue does not call the validator and keeps the previous behavior.
- Rescue prompt export now includes an explicit CALENDAR CAMPAIGN RESCUE LOCK so ChatGPT is warned that the imported package will be checked against the original campaign.
- Validation audit (status, confidence, model and reasoning) is stored inside existing `rescue_data`, occurrence metadata and technical log fields.

## Model configuration
The validator model is configurable through `CAMPAIGN_RESCUE_VALIDATION_MODEL` and then falls back to the existing carousel/editorial model configuration before the default model.

## Database
No SQL migration is required. v144.171 only uses existing JSON/JSONB fields.
