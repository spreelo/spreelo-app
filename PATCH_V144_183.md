# Spreelo v144.183 — Recurring credit pause & automatic resume

Built on v144.182.

## What changed

- Weekly recurring plans now use a stable `recurring_plan_group_id` so every weekday belongs to one durable plan.
- The next full weekly cycle is funded atomically. Spreelo no longer lets individual weekdays silently die one by one when credits run out.
- If the next complete cycle cannot be funded, the whole recurring plan is paused with `plan_pause_reason = insufficient_credits`.
- Credits still reserved for future weekdays in that plan are returned when the credit pause begins.
- If an adaptive weekly slot becomes more expensive at execution time and the extra credits are unavailable, Spreelo stops before paid generation, returns the complete plan's held reservations, finalizes that occurrence without an admin-rescue case, and pauses the whole plan.
- Failure/rescue paths now rejoin the same complete-cycle barrier even when the legacy rescue lifecycle could not reserve that weekday's next occurrence. This prevents one weekday from silently disappearing from an otherwise active plan.
- Missed posts during a credit pause are never backfilled. On resume, each weekday is scheduled at its next future local date/time.
- A credit-paused plan automatically attempts to resume after any legitimate increase in `user_credit_balances.credits_remaining`, including subscription credit refreshes, purchased credit packs and admin top-ups.
- Manual pauses are stored separately (`plan_pause_reason = manual`) and never auto-resume.
- Manual resume of a credit-paused plan reserves the complete next cycle before reactivating it.
- Weekly adaptive-content cost changes are reconciled against the held reservation before paid generation begins.
- Successful weekly runs and terminal failure/rescue paths converge on the same complete-cycle reservation barrier.
- Customer UI shows a localized “Paused – waiting for credits” state and explains how many credits the next full cycle needs.
- New visible copy is defined only through English source i18n keys, preserving Spreelo's normal translation/cache flow.

## Deployment

The release includes `spreelo-v144.183-CONSOLIDATED-SQL.sql`.

If v144.181 / v144.182 SQL was **not** run, run only the v144.183 consolidated SQL. Do not apply the older files first.

Recommended order:

1. Run the v144.183 consolidated SQL in Supabase.
2. Deploy the v144.183 application ZIP.
3. Verify one recurring plan with sufficient credits and one test account/plan that reaches a credit pause before production rollout.
