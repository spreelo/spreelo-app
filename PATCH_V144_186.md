# Spreelo v144.186 — Smart onboarding + secure admin team

**Built directly from the approved v144.183 package. No v144.184/v144.185 Codex application code is used as the base.**

## Smart onboarding

- Adds the approved compact onboarding recommendation modal to normal AI Content Studio entry.
- Keeps the approved information structure:
  1. Why we recommend this plan
  2. Plan settings
  3. Content types in the plan
- Shows real brand/profile evidence for audience, market and offering.
- Recommends only the three current goals: Sell more, Get more followers or Build trust.
- Recommends only 3 / 5 / 7 posts per week.
- Uses the existing v144.182 strategy to build the actual content mix.
- Shows real start date, publishing days, channels, estimated weekly credits and current week-to-week variation setting.
- Shows every unique content type in the proposed plan; there is no four-card truncation.
- Uses a text-free existing Spreelo visual in the hero.
- The popup stays a rounded modal on mobile; it does not turn into a full-screen white page.
- Activate starter plan uses the normal safe `savePlan()` path.
- Review and customize closes the popup while leaving the generated plan in AI Content Studio.
- Skip / X closes only for the current page visit.
- Normal customers see the popup until their first plan is successfully created. After that it stays suppressed.
- `johan@foldern.com` sees it on every normal AI Content Studio opening for testing.
- Campaign handoffs and direct-plan links bypass the onboarding popup.
- A background AI recommendation is cached for the next opening and never replaces the plan currently displayed, preventing activation-vs-AI race conditions.

## Admin team invitations

- Primary administrator defaults to `johan@foldern.com` through `SPREELO_PRIMARY_ADMIN_EMAIL`.
- Only the primary admin can open the team-management API.
- Admin invitations use 32 random bytes, base64url transport, SHA-256 hashes at rest, 48-hour expiry and single use.
- Acceptance requires the signed-in Supabase account email to exactly match the invited email.
- Accepted admins are stored server-side and receive the same protected `/admin` authorization path as configured admins.
- Accepted admins receive protected `app_metadata.spreelo_admin = true` so database/social capacity bypass stays synchronized.
- Revocation removes the protected metadata first. Metadata-removal failures are returned as hard errors rather than being ignored.
- Configured env admins cannot be revoked from the team-management UI.

## Current plan limits synchronized

Paid plans now use the current agreed capacity model in both application and database entitlement logic:

- Starter: 1 brand / 1 social account / 1 rolling plan
- Growth: 1 brand / 5 social accounts / 3 rolling plans
- Pro: 1 brand / unlimited social accounts / 5 rolling plans

The billing plan cards were updated to match these limits.

## i18n

All new customer/admin/email copy is stored as English canonical i18n keys in `lib/i18n/defaultLabels.js`, so Spreelo's existing translation/cache flow can translate it once per locale.

## SQL

Run `spreelo-v144.186-SQL.sql` on a database that already has v144.183.

`spreelo-v144.186-CONSOLIDATED-SQL.sql` is also included for a fresh consolidated handoff. It begins with the exact v144.183 consolidated SQL and appends only the v144.186 migration.

Do not rerun older entitlement migrations after v144.186, because they contain historical capacity values.
