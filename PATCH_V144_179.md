# Spreelo v144.179 — Brand 429 Rescue + Cost Guard

Base: **v144.178 Vercel Build Hotfix**.

## Purpose
Prevent repeated paid AI research when a website responds with HTTP 429 / rate limiting. A confirmed website 429 now becomes a persistent brand-level Rescue state instead of an automatic cooldown/retry loop.

## Runtime behavior
- The first confirmed website 429 routes the current generation occurrence directly to Admin Rescue.
- Automatic website-429 cooldown retries are no longer used by the active worker paths.
- The affected brand is persisted as `website_access_status = rate_limited_rescue` with status code `429`.
- Future **website-dependent** generation jobs for that brand are intercepted before credit checks, product research, OpenAI calls, image generation, or website retrieval.
- Those pre-gated jobs create normal durable Admin Rescue work/review items, but repeated critical admin alerts and repeated customer failure emails are suppressed.
- Existing completed drafts can still be recovered before the 429 pre-gate, so already-created content is not discarded.
- Calendar-campaign carousels no longer use the campaign visual fallback when the underlying failure is a website 429; they go to Rescue immediately.
- Non-website-dependent posts are not blocked by the brand's 429 Rescue state.

## Admin controls
- Customer overview has a dedicated Website status column and a `429 Rescue` filter.
- Brands in 429 Rescue are clearly marked.
- Each brand has a translated `429 Rescue` ON/OFF control.
- Turning the control OFF restores normal website generation by resetting the website access state to `not_checked`.
- If a later real run receives another website 429, Spreelo automatically enables 429 Rescue again.
- Brand-analysis save paths preserve an active 429 Rescue state so unrelated analysis updates cannot accidentally clear the admin setting.

## i18n
- All new customer/admin UI text uses translation keys with English as the source language.
- The mass-test carousel name/description now use the existing `automation.contentType.carousel_website_item.*` translation keys instead of hardcoded English.

## Database
No SQL migration is required. v144.179 reuses the existing `brand_profiles.website_access_*` columns.
