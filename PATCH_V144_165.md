# Spreelo v144.165 — Sol-locked editorial product headlines

## Goal
Reduce visible spelling mistakes in GPT-Image-2 Product posts without giving up GPT-Image-2's integrated typography/design and without adding a second paid image generation.

## Changes
- Product-post headline wording is now finalized **before** GPT-Image-2 runs.
- GPT-5.6 Sol (`gpt-5.6-sol`) receives:
  - the already-verified product context,
  - selected brand/market/language/tone context,
  - bounded finished post context,
  - real calendar-campaign context only when the rule is actually campaign-scoped,
  - one downsized product-image vision input at `detail: low`.
- Sol is not given web-search or other tools. It cannot start a second website/product research path.
- Sol drafts and silently proofreads the headline in one request and returns only one structured headline.
- Local guards reject generic, duplicate, overlong or product-name-redundant headline output.
- GPT-Image-2 receives the approved headline as immutable visible copy, plus a character-by-character spelling reference.
- GPT-Image-2 retains freedom over typography, capitalization, line breaks, placement, hierarchy, background and overall composition; it no longer decides the headline wording.
- If Sol is unavailable, Product-post generation does not fail solely because of that call. Spreelo uses a safe pre-image caption-derived headline if one already exists; otherwise GPT-Image-2 is forbidden to invent a headline and uses only verified product copy.
- No second GPT-Image-2 spelling-repair generation was added.

## Cost tracking
- Added pinned GPT-5.6 Sol text/input pricing to the existing generation-cost ledger so the new vision+copy request is included in the real per-post cost summary.
- The request uses `reasoning.effort: none`, low-detail vision and tightly bounded text/output to keep cost small.

## Regression safety
- Product Engine, Store Map, web-research fallback and v144.164 explicit calendar-campaign classification are unchanged.
- Social Channels remains byte-for-byte unchanged.
- No SQL/database migration is required.
