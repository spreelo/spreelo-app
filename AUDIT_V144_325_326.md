# Spreelo AI Control — review of v144.325 and v144.326

Audit performed on v144.327 source and compared with v144.324–v144.326 ZIP archives.

## v325
- The added manual-post and campaign-planning model purposes have SQL seeds (`ON CONFLICT DO NOTHING`), avoiding changes to existing choices.
- Changed calls keep their previous hardcoded model IDs as fallbacks. Request-local model scope is used for manual post and campaign planning.
- Brand analysis and automation changes are limited to model selection; generation prompts were not rewritten.
- Model capabilities remain a static allowlist. This is conservative, but it does not constitute automatic capability validation.

## v326
- The daily, CRON_SECRET-protected discovery route accesses OpenAI `/v1/models` and only `ai_model_catalog` in Supabase. It does not change active models.
- New model IDs are recorded as `pending_review`; they do not automatically appear in selectable dropdowns.
- The existing version only wrote `last_seen_at` at insertion time. This reviewed ZIP fixes that by updating it for listed existing models, without changing approval/capability fields.
- Kling discovery, automated compatibility verification and dynamic dropdown connection are NOT present in v326 (phase 1).

## Safety and limitations
- Reviewed migration SQL in v327 contains the additive v325/v326 migrations; no extra SQL is needed for the timestamp fix.
- Unit checks and source syntax checks are not substitutes for a production Next.js build or real OpenAI/Supabase/Resend tests.
- The existing product/content generation logic and Shotstack were not modified by this audit correction.
